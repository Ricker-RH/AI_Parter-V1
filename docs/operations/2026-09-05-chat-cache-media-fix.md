# 聊天重进、图片缓存与语音修复

用户授权优化真人聊天重进刷新、底部定位、图片重复下载及接收方语音不可操作的问题。本轮未提交或部署，基于 HEAD `6a7e887`。

## 行为

- 真人聊天正文存入现有 QueryClient，按账号和会话隔离。重进先显示缓存，再从服务端已确认的 history sequence 补拉消息。实时消息和发送响应不推进补拉游标，避免跳过并发消息。
- 首次进入在绘制前定位底部，ResizeObserver 跟随消息区域和列表高度变化。向上翻阅时停止自动贴底；主动发送后回到底部。
- 图片文件作为 Blob 保存在附件查询的内存数据中，附件续签成功后复用已有字节。组件挂载创建对象 URL，卸载释放 URL；账号变化由 AppQueryProvider 清理私有查询。图片尺寸来自服务端附件元数据。
- 沿用应用的 10 分钟未使用查询回收策略；不写入 localStorage、IndexedDB 或永久磁盘缓存。整页刷新后需重新下载。R2 GET CORS 无法使用或文件获取失败时回退到既有签名图片显示路径，此回退不保证字节缓存。
- 签名链接仍为短时有效，图片授权仍定期检查。语音在播放时检查过期并续签，避免定时替换 audio src 导致正在播放的语音中断。
- 语音控件改为 300px 明确宽度并限制不超过容器，修复收发两侧网格收缩导致的 0px/44px 控件。
- 回到前台与断线轮询同时补拉打开会话的正文，保持已有消息可见。

## 验证

- 6 个 Web 测试文件共 45 项通过：HumanChat、HumanInbox、HumanMediaMessage、HumanMediaControls、HumanChatQueryProvider、HumanChatCache。
- 新增重进缓存、图片字节复用、历史游标漏消息、断线补收、延迟尺寸变化与语音不中途续签的回归覆盖。
- `HUMAN_MEDIA_BROWSER_TEST=1` 的 root/API 两个浏览器测试文件共 4 项通过。Chromium/WebKit 在 390/900/1440 宽度检查两侧语音控件和横向溢出；浏览器合成音频另页播放通过；现有服务端录音容器校验测试通过。
- Web 生产构建、TypeScript、107 页面生成和预渲染检查通过；git diff --check 通过。

浏览器播放测试传递实际录制字节到另一页面，但不代表已完成线上双账号、真实麦克风、真实 iPhone 或跨浏览器编码组合的完整验收。原有用户未提交文件均保留。
