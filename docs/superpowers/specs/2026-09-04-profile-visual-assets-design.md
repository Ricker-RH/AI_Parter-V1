# AIFANS 个人资料视觉资产与编辑页设计

日期：2026-09-04

## 目标

让人类用户可以在“编辑资料”中维护头像和个人主页顶部背景，并保证头像更新后在端内所有位置一致显示。编辑资料统一为标准独立页面，主页资料区的纵向间距同步回归现有 4/8px 设计节奏。

本功能按可长期上线的资产上传、数据绑定和缓存同步方案实现，不保存浏览器临时地址，不通过页面级补丁分别刷新头像。

## 范围

### 本阶段包含

- 上传、更换和恢复默认头像
- 上传、更换、移除个人主页背景图
- 一组由设计系统管理的纯色背景
- 背景图焦点调整与响应式裁切
- 编辑资料在手机、中屏和大屏统一使用独立页面
- 保存前本地预览，保存后统一生效
- 当前窗口与其他已打开窗口的账号资料同步
- 端内所有当前用户头像入口统一展示
- 上传校验、失败恢复、资产绑定和旧资产清理
- 主页“编辑资料”按钮与下方标签栏间距修正

### 本阶段不包含

- 任意颜色选择器
- 头像或背景历史版本
- 滤镜、贴纸、动态背景或视频背景
- IP/Creator 资料资产改造
- 用户上传内容的人工审核后台

## 方案选择

### 未采用：直接保存图片 URL

客户端直接向资料接口写入 URL 虽然改动少，但无法可靠控制来源、生命周期、权限和垃圾回收，也会让临时上传地址进入长期数据，因此不采用。

### 采用：独立个人资料资产

复用项目已有的签名上传与对象存储能力，为人类用户资料建立独立的资产语义。客户端只提交服务端签发并验证过的资产标识；数据库保存资产关系和背景表现配置；API 负责输出可展示的图片地址。

### 暂不采用：全站通用媒体资产中心重构

完整的多租户媒体资产中心扩展性更强，但会扩大本需求边界。当前方案保持清晰的领域边界，同时允许未来迁移到统一资产中心。

## 页面与交互

### 编辑资料页面

编辑资料在所有尺寸均使用可深链的独立路由，不再在中大尺寸使用弹窗。

- 顶部复用标准详情页导航：返回、标题“编辑资料”、保存操作。
- 从个人主页进入时，返回或取消回到原页面并恢复原滚动位置。
- 存在未保存修改时返回，提示放弃修改或继续编辑。
- 表单首段为个人主页视觉预览，之后依次为昵称、用户名、简介和语言。
- 所有字段修改立即反映在预览区，但只有点击“保存”才写入资料。
- 保存期间禁用重复提交并显示进度；失败时保留文字、图片预览和焦点设置，提供重试。
- 手机端整页滚动；中大尺寸使用现有主内容框架和受控表单宽度，不使用浮层或额外营销式卡片。

### 头像编辑

- 点击头像选择本地图片。
- 上传后进入圆形裁切预览；原始裁切区域为正方形。
- 支持重新选择图片和恢复默认头像。
- 默认头像继续使用稳定的姓名首字母回退。
- 裁切确认只改变待保存状态；保存资料后才全端生效。

### 背景编辑

背景存在两种互斥模式：预设纯色和上传图片。

- 纯色只保存设计系统 `colorKey`，不接受任意 CSS 色值。
- 图片始终覆盖背景区域，不允许因比例不同产生留白。
- 用户可以拖动选择视觉焦点；同时提供键盘或按钮式位置调整，避免依赖精细拖拽。
- 焦点以归一化 x/y 坐标保存，所有断点使用同一焦点计算裁切。
- 支持移除图片并回到默认纯色。

### 响应式展示

手机、中屏和大屏读取同一份资料数据，只调整背景区域高度和裁切视口。

- 图片使用 `cover` 语义和保存的焦点坐标。
- 页面预留固定宽高比，加载前即占位，避免布局偏移。
- 输出响应式图片尺寸与现代格式，避免手机加载桌面原图。
- 主页头像与背景均包含加载失败回退。

### 主页间距修正

“编辑资料”按钮下方现有大块空白不是安全区，也不符合现有间距体系。

- 按钮与资料标签栏之间使用现有间距 token。
- 手机标准间距为 16px；中大尺寸标准间距为 24px。
- 标签栏继续保留满足触控要求的自身高度。
- 页面安全区只作用于固定底部导航和页面末端，不插入按钮与标签栏之间。

## 数据模型

资料视觉字段属于人类用户资料，不复用 Creator/IP 的 avatar、cover 引用关系。

建议为 `human_profiles` 增加：

- `avatar_asset_id`：可空，引用已确认的个人资料资产
- `background_type`：`color` 或 `image`
- `background_color_key`：可空，引用允许的预设色 token
- `background_asset_id`：可空，引用已确认的个人资料资产
- `background_focal_x`：0 到 1，图片模式使用
- `background_focal_y`：0 到 1，图片模式使用
- `version` 或等价并发控制字段
- `updated_at`

约束：

- `background_type = color` 时禁止绑定背景图片。
- `background_type = image` 时必须存在背景资产。
- `colorKey` 必须属于服务端允许列表。
- 头像资产必须属于当前用户且角色为 avatar；背景资产角色必须为 background。
- 背景焦点坐标由数据库约束在 0 到 1 之间。

建立个人资料资产及上传预留记录，至少包含所有者、角色、对象键、MIME、字节数、像素尺寸、校验状态、绑定状态、创建时间和过期时间。资产所有权不得由客户端自由指定。

## API 与上传流程

### 上传流程

1. 客户端向 API 申请 avatar 或 background 上传意图。
2. API 校验登录状态、角色、允许的 MIME、大小上限和上传频率，并生成不可猜测对象键。
3. 客户端使用短时签名地址直接上传对象存储，显示独立上传进度。
4. 客户端通知 API 完成上传。
5. API 读取对象元数据并实际解码图片，校验真实格式、像素尺寸和体积。
6. 服务端生成所需衍生图并将预留标记为可绑定。
7. 用户点击“保存”时，资料更新接口在事务内绑定新资产和资料字段。
8. 未绑定预留到期后由清理任务删除；替换下来的旧资产经过宽限期再删除。

浏览器生成的 blob URL 只用于本地预览，永远不写入数据库。

### 资料读取与更新

- `GET /api/me` 和公开资料响应返回统一的头像及背景表现模型。
- `PATCH /api/me` 扩展头像资产、背景配置和资料版本字段。
- 更新请求使用契约校验并拒绝未知字段。
- 使用乐观并发控制；资料版本已变化时返回冲突，让用户刷新或重新提交，不静默覆盖。
- 资产绑定、旧资产解绑和资料版本更新位于同一数据库事务。

## 图片处理与安全

- 允许经过明确配置的 JPEG、PNG、WebP；是否启用 HEIC 取决于部署图像处理能力。
- 校验文件签名和解码结果，不能只信任扩展名或 `Content-Type`。
- 限制原始字节数、像素总量、宽高范围和解码时间，防止图片炸弹。
- 移除不需要的 EXIF 和定位信息，修正方向后生成衍生图。
- 页面使用适合视口的 WebP/AVIF 或等价优化格式。
- 对象键由服务端生成；公开主页使用只读 CDN 地址，上传凭证保持短时有效。
- 上传和确认接口都实施用户级速率限制。

## 全端头像一致性

建立单一的当前账号资料源和共享头像组件，避免各页面自行截取首字母或缓存 URL。

共享 Avatar 组件负责：

- 图片、加载占位和首字母回退
- 圆形裁切、标准尺寸与响应式 `sizes`
- 图片加载失败状态
- 替代文本、焦点和交互标签

头像保存成功后：

- 原子更新当前账号客户端状态。
- 失效 `/api/me` 及公开当前用户资料缓存。
- 触发依赖当前账号的服务端视图刷新。
- 通过 `BroadcastChannel` 或等价浏览器机制通知同源其他窗口重新获取资料。
- 新导航和刷新均从持久化资料关系读取新头像。

帖子和评论不得复制用户头像 URL 作为长期快照。历史内容通过作者 profile ID 关联读取当前头像，因此用户更换头像后，历史帖子和历史评论也显示新头像。

## 错误处理与恢复

- 上传失败显示具体阶段和可恢复操作，不清空表单。
- 图片校验失败指出格式、尺寸或体积问题。
- 保存失败保留所有待提交状态并允许重试。
- 网络中断后已验证但未绑定的上传仍可在有效期内继续保存。
- 旧头像或背景只有在新资料成功提交并经过宽限期后才回收。
- 多窗口编辑冲突必须显式提示，不能用最后一次写入静默覆盖。

## 无障碍

- 上传、移除、重新选择、调整焦点和保存均有可见文字或可访问标签。
- 所有点击区域至少 44×44px。
- 键盘可以完成选择、调整和保存；可见焦点不被移除。
- 纯色背景组合保证资料文字达到 WCAG 对比度要求。
- 背景为装饰图时不重复朗读；头像具有与用户身份相关的替代文本。
- 动画尊重 `prefers-reduced-motion`。

## 验收标准

- 手机、中屏和大屏均通过独立编辑资料路由完成相同编辑流程。
- 上传头像、背景图片和选择纯色均需点击保存后才生效，取消不会改变已保存资料。
- 背景焦点在不同尺寸裁切下保持主体位置。
- 更新头像后，主页、内容、历史评论、评论输入、消息、通知和头像弹窗显示一致。
- 同一账号的另一个浏览器窗口能在保存后同步获得新资料。
- 上传失败、保存失败和版本冲突都不会丢失用户已经填写的内容。
- 非当前用户不能绑定、读取上传凭证或删除他人的待处理资产。
- 主页编辑按钮与标签栏之间不再出现异常大块留白。
- 图片加载不会造成明显布局偏移，且移动端不会请求桌面原图。
- 契约、数据库约束、API、共享组件和关键响应式页面均有自动化测试。

## 实施边界

实施按以下四个边界组织，但共享同一数据契约：

1. 数据库、上传预留、图片验证和资料 API。
2. 独立编辑资料页、上传/裁切交互和响应式主页背景。
3. 当前账号状态、跨窗口同步及共享 Avatar 组件迁移。
4. 主页间距修正、回归测试和部署验收。

任何页面不得自行增加头像刷新补丁；任何上传入口不得绕过服务端签发、校验和资产绑定流程。
