# AIFANS 独立管理后台设计

## 目标

把 `/[locale]/admin` 从普通用户站导航中分离出来，并保证从后台触发的登录会安全返回原后台地址。第一期后台只包含内容运营和 Creator 审批；数据分析以后接入。

## 路由与权限

- `/[locale]/admin`：内容运营。
- `/[locale]/admin/creator`：Creator 审批。
- 两个页面继续通过服务端 `GET /v1/admin/access` 逐请求校验权限，并强制动态渲染。
- 未登录访问时跳转到 `/${locale}/auth/sign-in?next=<原后台路径>`。
- 登录页只接受当前 locale 下的 `/admin` 或 `/admin/creator` 作为回跳目标；缺失或非法目标回退到 `/${locale}`，避免开放重定向。
- 已登录但不是 operator 时只显示无权限状态，不渲染后台功能。

## 后台 Shell

- 根布局根据当前 pathname 在用户 Shell 和后台 Shell 之间切换，URL 不变，不移动现有页面目录。
- 后台桌面导航只包含：内容运营、Creator 审批、返回用户站、退出登录。
- 后台移动导航提供同样入口，不显示首页、搜索、通知、消息、收藏、个人资料或 Creator 中心等用户导航。
- 后台不渲染用户站右侧推荐栏。
- 黑白主题、双语和现有响应式断点继续复用。

## 登录回跳

- Auth 页面解析并验证 `next`。
- 邮箱登录和 Google 登录都使用验证后的回跳地址。
- 登录/注册切换链接保留合法 `next`。
- 登出仍回到当前 locale 的用户站首页。

## 失败处理

- Auth/API 暂不可用：后台显示已有的服务不可用文案，不泄露后台数据。
- 普通用户：显示已有的 operatorRequired 文案。
- 非法 `next`：静默回退用户站首页，不反射到页面或 OAuth callback。

## 验证

- 单元测试覆盖 Shell 路由选择、后台桌面/移动导航、合法和非法回跳、邮箱与 Google 登录目标。
- 页面测试覆盖匿名后台重定向、普通用户拒绝、operator 正常渲染。
- 全量 Web/API 测试、类型检查和生产构建必须通过。
- 生产 smoke：匿名 `/admin` 跳登录；登录后回 `/admin`；后台两个入口切换不离开后台；“返回用户站”明确退出后台界面。

## 非目标

- 本次不新增数据分析页面、用户管理、系统设置或新的后台权限角色。
- 本次不改数据库结构、运营 API 的业务行为或 Creator 审批规则。
