# AIFANS 频道、导航与悬浮创作入口设计

日期：2026-09-04

## 目标

新增一个轻量、可长期扩展的频道功能，让用户按主题发现 IP 并集中浏览这些 IP 发布的内容。同时重新整理手机端一级导航，将喜欢和收藏保留在个人主页中，并把现有创作入口改为只在指定一级页面展示的悬浮按钮。

本阶段不改变现有创作页面，不引入频道关注、个性化频道推荐或用户创建频道。

## 产品范围

### 本阶段包含

- 频道首页
- 频道搜索
- 频道详情页
- 频道 IP 推荐区域
- 完整频道 IP 列表
- 频道内容聚合流
- 平台管理员维护频道及分配 IP 的能力
- 手机、中尺寸和桌面布局适配
- 手机端四项底部导航
- 指定一级页面的悬浮创作按钮
- 数据库、API、缓存、分页、权限、测试和部署适配

### 本阶段不包含

- 用户关注频道
- 基于用户行为的频道个性化
- 用户或 IP 自助创建频道
- 频道内二级搜索
- 独立搜索服务
- 重做创作页面
- 删除喜欢、收藏页面或既有 URL

## 信息架构

### 频道首页

路由为 /[locale]/channels。

页面使用现有 AIFANS 黑白、轻边界、内容优先的视觉语言：

- 页面大标题直接显示“频道”，不使用标题卡片或外框。
- 标题下显示一句弱化说明。
- 在频道列表上方提供频道专用搜索框。
- 搜索在当前页面返回频道结果，不跳转至新页面。
- 频道以紧凑条目呈现，包含识别图、名称、简介、IP 数量和进入提示。
- 频道之间使用现有细分隔线，不使用厚重阴影或营销式大封面。
- 后台展示顺序作为默认频道排序。

频道搜索只匹配频道名称、简介和搜索别名。IP 与内容继续由现有全局搜索承担。

### 频道详情页

路由为 /[locale]/channels/[slug]。

顶部沿用现有详情页导航，显示返回按钮和频道名称。页面中不再重复展示频道名称、图标和简介组成的大块频道介绍区域。

正文顺序固定为：

1. 频道 IP 推荐区域
2. 频道内容流

频道 IP 区域：

- 标题为“频道 IP”。
- 默认显示推荐顺序靠前的若干 IP。
- 每个 IP 使用现有头像与名称表现。
- 点击 IP 进入现有 IP 主页。
- “查看全部”进入完整频道 IP 列表。
- 推荐顺序由服务端统一返回，页面不计算或写死热度。

内容流：

- IP 区域之后直接显示内容卡片，不显示“最新内容”标题。
- 只聚合该频道中已发布 IP 的公开内容。
- 内容默认按最新发布时间倒序。
- 复用现有内容卡片、图片、头像弹窗和四项互动指标。
- 使用稳定游标分页。

频道详情属于二级页面，不显示悬浮创作按钮。

### 频道 IP 列表

路由为 /[locale]/channels/[slug]/profiles。

列表复用“我的主页－关注列表”的信息密度和视觉结构：

- IP 头像
- 展示名称
- 用户名
- 简介
- 条目分隔线

列表按频道推荐顺序展示并使用稳定游标分页。点击条目进入现有 IP 主页。该页面属于二级页面，不显示悬浮创作按钮。

## 响应式布局

所有尺寸使用同一数据模型、API 和业务组件，只通过现有断点调整布局。

### 手机尺寸

- 频道首页使用单列频道列表。
- 频道搜索框位于标题下方，不吸顶。
- 频道详情的推荐 IP 使用单行横向列表；空间不足时横向滚动。
- 内容流保持单列。
- 频道 IP 完整列表保持单列。
- 页面底部预留安全区和滚动缓冲，不能被底部导航或悬浮按钮覆盖。
- 显示四项固定底部导航。

### 中尺寸

- 使用现有紧凑侧栏，不显示手机底部导航。
- 频道首页在空间允许时使用两列紧凑频道条目。
- 频道详情保持适合阅读的单列正文，不把内容卡片拉满窗口。
- 推荐 IP 一行显示更多项目。
- 完整 IP 列表保持单列并限制可读宽度。

### 大尺寸

- 使用现有完整左侧导航。
- 频道首页使用两列频道条目并限制主内容最大宽度。
- 频道详情保持单列内容流，避免超宽正文。
- 频道 IP 推荐区利用可用宽度显示更多 IP。
- 完整 IP 列表保持单列，与现有关注列表一致。

## 导航设计

### 手机底部导航

手机底部导航固定为四项：

1. 首页
2. 频道
3. 消息
4. 我的

移除原底部导航中的创作加号和喜欢、收藏聚合入口。

喜欢与收藏继续在“我的”页面中显示。既有 /liked、/bookmarks 和 /activity 路由保留，以兼容桌面导航、已有链接和返回地址。

### 中大尺寸左侧导航

- 新增“频道”入口。
- 继续保留喜欢和收藏独立入口。
- 其他现有导航行为不变。

### 悬浮创作按钮

原手机底部中间加号改成右下角悬浮圆形加号。

显示范围：

- 首页根页面
- 频道首页
- 消息列表一级页面

不显示范围：

- 内容详情
- 频道详情
- 频道 IP 列表
- 单个聊天
- IP 主页
- 我的主页
- 喜欢与收藏
- 设置、管理与创作流程

按钮继续跳转现有 /[locale]/creator。创作页面和创作流程本阶段保持不变。

显示规则由共享应用外壳中的集中式路由元数据决定，不能由各页面分别添加隐藏 CSS。按钮使用固定定位、移动安全区和至少 44px 的点击区域。相关一级页面必须提供足够的底部内容留白。

## 数据模型

### channels

正式频道实体，建议字段：

- id：UUID 主键
- slug：稳定且唯一的公开路径标识
- name：频道名称
- description：频道简介
- image_object_key：可选频道识别图对象键
- search_document：由名称、简介和别名生成的标准化搜索文本
- status：draft、published 或 archived
- sort_order：频道首页人工排序
- created_at
- updated_at

公开查询只返回 published 频道。slug 创建后默认保持稳定；改名不自动改 slug，避免外部链接失效。

### channel_search_aliases

频道搜索别名使用独立关系表或等价的正规化结构：

- channel_id
- alias
- normalized_alias

频道与规范化别名组合唯一。中文、英文名和常见简称可同时维护。

### channel_ip_profiles

频道与 IP 的多对多关系：

- channel_id
- ip_profile_id
- is_primary
- curation_weight
- created_at
- updated_at

约束：

- channel_id 与 ip_profile_id 组合唯一。
- 只能关联 account_kind 为 ip 且公开状态有效的 IP；写入通过管理命令和数据库校验共同保证。
- 对每个 IP 建立部分唯一索引，保证最多一个 is_primary 为真。
- 删除或归档频道不删除 IP、内容或互动数据。

不向 ip_profiles 添加逗号字符串、JSON 标签或单一 channel_id。

## 搜索与排序

### 频道搜索

- 服务端执行搜索，不要求浏览器先加载全部频道。
- 输入使用约 300ms 防抖。
- 对规范化搜索文本使用 PostgreSQL 成熟的模糊匹配索引；优先采用 pg_trgm GIN 索引以支持中文和子串查询。
- 结果先按匹配质量，再按 sort_order，最后按稳定主键排序。
- 搜索和普通列表都使用有上限的分页参数。

本阶段不引入 Elasticsearch、Meilisearch 或独立搜索基础设施。

### IP 推荐顺序

“热度”作为产品概念，不在前端显示未经定义的实时数值。

第一阶段使用可解释且稳定的服务端顺序：

1. channel_ip_profiles.curation_weight
2. 现有 ip_profiles.feed_weight
3. 最近公开内容时间
4. ip_profile_id 稳定兜底

排序接口与页面解耦。未来可将近期互动、内容质量或离线计算得分接入同一排序层，不需要修改页面或频道关系表。

不在每次频道请求中扫描全量点赞、评论、收藏和分享记录计算实时热度。

### 内容顺序

频道内容按 published_at DESC、id DESC 排序。游标同时包含时间和 ID，保证时间相同、翻页和并发发布时结果稳定。

## API 设计

沿用现有 API、端口与仓储分层，不引入第二套后端框架。

公开读取接口：

- GET /v1/channels
- GET /v1/channels/:slug
- GET /v1/channels/:slug/profiles
- GET /v1/channels/:slug/posts

列表接口支持 limit、after；频道首页额外支持 q。所有参数使用现有契约验证方式，limit 有明确上限。

管理接口：

- 创建和编辑频道
- 发布、归档频道
- 管理搜索别名
- 为频道添加或移除 IP
- 设置主频道
- 调整 curation_weight 和频道 sort_order

管理写接口沿用现有管理员授权边界和审计方式，不允许普通用户写入频道配置。

## 缓存与数据一致性

- 频道目录和频道详情属于公开、低频变化数据，可使用现有公共缓存策略。
- 频道内容流沿用现有内容缓存与失效方式。
- 管理操作完成后使相关频道目录、详情和成员列表缓存失效。
- 频道归档后公开接口返回正式的不存在状态，不输出残缺频道。
- 数据库写操作使用事务，频道成员关系和主频道变更必须原子完成。

## 页面状态

频道首页和详情页需要覆盖：

- 骨架加载
- 空频道目录
- 搜索无结果与清空搜索
- 频道暂无 IP
- 有 IP 但暂无内容
- 分页加载
- 内联失败与重试
- 已归档或不存在频道

失败不能导致导航、底部安全区或既有页面失效。

## 迁移与兼容

- 采用新增表和新增索引的前向迁移，不重写现有 profiles、ip_profiles、posts 或互动数据。
- 初始频道和 IP 分配通过受控 seed 或管理命令执行，不在前端写死。
- 喜欢、收藏和创作入口的既有路由继续可访问。
- 数据库迁移、API 和 Web 按兼容顺序部署，避免 Web 在 API 或表尚未就绪时调用新接口。
- 测试环境先应用并验收，生产环境数据不自动同步。

## 测试与验收

### 数据库

- 表约束、唯一索引和主频道部分唯一索引
- 多频道归属
- 频道归档不删除 IP 与内容
- 搜索索引和稳定排序
- 游标分页无重复、无遗漏
- 管理事务和权限

### API

- 频道目录、搜索、详情、IP 列表和内容流契约
- 无效 slug、无效游标、limit 上限
- 只返回 published 频道和公开 IP
- 管理员授权
- 缓存失效

### Web

- 手机四项导航顺序与激活状态
- 桌面频道、喜欢和收藏导航
- 悬浮按钮显示矩阵和 /creator 跳转
- 频道搜索防抖、无结果和重试
- 频道详情无重复介绍区、无“最新内容”标题
- “查看全部”进入频道 IP 列表
- 手机、中尺寸和大尺寸响应式布局
- 安全区、固定导航和页面底部缓冲

### 发布验收

- 完整测试、类型检查和生产构建
- 数据库迁移在 Preview 数据库验证
- API Preview 健康检查和频道接口验证
- Web Preview 桌面、平板、手机视觉验收
- 频道搜索、分页、导航、IP 跳转、内容跳转和创作入口实测

## 实施拆分

设计与计划批准后，可并行拆成以下任务：

1. 数据库迁移、仓储与集成测试
2. API 契约、公开读取与管理员写入
3. Web 导航、悬浮入口与路由策略
4. 频道页面、搜索、响应式组件与页面测试
5. 汇总集成、独立代码复核、Preview 部署与视觉验收

数据库契约先固定，其他任务基于同一契约并行，最终统一集成，避免各子任务自行发明不同数据结构。
