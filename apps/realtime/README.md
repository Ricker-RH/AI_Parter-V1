# Isolated realtime gateway foundation

This package is not a production chat service and has not been deployed. It supplies Workers routing, one SQLite Durable Object mailbox per human profile, and hibernatable WebSocket authentication/subscriptions/fanout. PostgreSQL remains authoritative; reconnecting clients must fetch persisted messages and cursors through the API. There is no event durability/replay guarantee here.

## Wire contract

- Browser connects `GET /connect/{profileId}` with an exact configured HTTPS Origin. Query parameters are rejected (tickets must not enter URLs/logs).
- First frame: `{ "v": 1, "type": "auth", "ticket": "..." }`. Gateway redeems it via trusted API and requires returned profile to match mailbox. Success: `{ "v": 1, "type": "auth_ok" }`; failure: `auth_error` then close. Send another fresh auth ticket before expiry to renew; subject cannot change.
- Subscribe/unsubscribe: `{ "v": 1, "type": "subscribe", "conversationId": "uuid" }` (or `unsubscribe`). No sender/profile fields are accepted. Denied subscriptions receive no events.
- Trusted API posts strict `HumanRealtimeEvent` directly to `POST /internal/events/{recipientProfileId}`, with `Authorization: Bearer REALTIME_INTERNAL_SECRET`. Only persisted/authorized server events belong here. API chooses recipients; gateway independently checks each live subscription before sending. `access_revoked` removes the subscription and is delivered to its former subscriber without demanding membership that was just revoked.
- Ticket redemption: `POST {UPSTREAM_API_URL}/v1/internal/realtime/redeem` with `{ticket,origin}`. Origin is captured from the HTTP handshake, never client JSON. Return `{subject,profileId,sessionId,sessionExpiresAt}` (sessionId UUID; expiry epoch milliseconds, maximum five minutes ahead).
- Subscription and every data-event authorization: `POST .../authorize` with `{subject,profileId,sessionId,conversationId,eventType?}`. Return `{allowed:boolean,presenceAllowed:boolean}`. API must recheck current membership, blocks, subject/profile ownership and durable session validity; presence additionally checks both participants' preferences. Both internal endpoints require the server secret, distinct from ticket signing keys.

## Safety bounds

Before resolving a DO stub, the Worker requires its native `ADMISSION_LIMITER` binding and a valid trusted `CF-Connecting-IP`; missing binding/error returns 503, absent/invalid edge IP returns 403, exhausted limit returns 429. `X-Forwarded-For` is ignored. The isolated test namespace `2026090401` allows ten handshakes/IP/ten seconds in each Cloudflare location, independent of the user-controlled mailbox path. This integer is an explicitly selected test configuration namespace, not an account ID; an operator must confirm it does not collide with another binding before deployment. Cloudflare documents these limits as approximate, location-local and eventually consistent. Shared IPs can be throttled together; this pre-authentication abuse guard is not a billing or user quota system.

Per profile: five authenticated devices and a separate pool of ten pending handshakes, each with a ten-second deadline. Pending sockets do not consume authenticated slots or evict existing devices. Promotion checks the authenticated cap after trusted redemption, serialized within the DO. Further bounds: 32 subscriptions/socket; 30 incoming frames/ten seconds; 8 KiB client frames; 16 KiB internal events; 4 KiB upstream responses; five-second upstream timeout; authorization expiry capped at five minutes. Idle authenticated sockets can hibernate until expiry; there is no artificial idle cutoff. Clients should renew using a fresh single-use ticket before expiry or reconnect. Persisted alarms enforce expiry without frames. Sending events never extends authorization. Close codes: 4400 invalid input, 4401 authentication denial, 4408 timeout/expiry (retryable with fresh ticket), 4429 bounds, 1011 upstream failure.

State (including origin, mailbox, identity, expiry, subscriptions and rate window) lives in `serializeAttachment`, not process-only maps. DO event handlers serialize asynchronous mutation with `blockConcurrencyWhile`. Alarm scheduling is persisted. No WebSocket `accept()` or ordinary event listeners are used; `ctx.acceptWebSocket` enables hibernation. The runtime implements the WebSocket handshake; no custom protocol crypto. No tickets, bodies, subjects or secrets are logged; Workers observability is disabled in this example config.

## Local verification and configuration

From workspace root: `pnpm --filter @aifans/contracts build`, `pnpm --filter @aifans/realtime typecheck`, `pnpm exec vitest run --project realtime`. Package `check:bundle` is a Wrangler dry run, not a deployment. No deploy script is provided.

`pnpm --filter @aifans/realtime test:runtime` runs the bundled production entrypoint in real local workerd through the existing pinned Wrangler/Miniflare toolchain. It tests HTTP upgrade/origin admission, trusted auth, session-bound subscription authorization, typing event delivery, presence denial, blocking after subscription, invalid mailbox identity, redirect rejection, and alarm-driven retryable expiry. Upstream HTTP calls are intercepted by an in-process API fixture; no Cloudflare account, remote resource, real credentials or external API is used. This exposed and regression-tests a Workers-specific fetch constraint: redirect mode must be `manual`, with non-2xx rejected, since Workers does not implement `error` mode. This verifies runtime APIs, not actual production network or process-eviction hibernation behavior.

Only an explicitly named `test` environment is configured, with `new_sqlite_classes` migration. `workers_dev` and preview URLs are disabled. Origins and API URL intentionally default empty and the secret is absent: all requests return 503 until configured. Do not put secrets into Wrangler vars or source. A real account, secret, isolated test hostname/route, origin and trusted HTTPS API require operator configuration/approval. This package neither creates nor modifies Cloudflare resources. SQLite compatibility is required for Free-plan DO support; no paid resources are requested.

## Remaining integration and operational gates

Before public exposure, verify account entitlements, namespace isolation, quotas/budgets and alarms. Native edge admission and profile-local bounds do not guarantee immunity to distributed denial-of-service or exhaustion of the pending handshake pool. Verify actual deployed hibernation, alarms, revocation races, origin policy, upstream session revocation and browser reconnect/auth renewal with real service bindings. Unit tests use injected socket/upstream ports and do not establish deployed guarantees. API outbox delivery, recipient selection, backpressure/retry/deduplication and backlog synchronization belong to API integration. No push-notification or offline-presence generation is implemented. Internal URLs must not redirect. Prefer private service connectivity when configuring upstream access.

Browser typing/presence is not end-to-end implemented: the transport sends only auth and subscribe/unsubscribe controls, accepts typed inbound events, and currently has no application-page caller. The gateway deliberately rejects browser-originated typing/presence publishing; it can fan out trusted API events (presence additionally gated by preference authorization). There is no browser typing action endpoint/emitter, online lifecycle publisher, heartbeat/last-seen presence model, or chat-page rendering wired here. Runtime typing fanout tests establish only that the gateway can deliver a trusted event; they do not imply a working typing indicator feature.

Based on current official [hibernation example](https://developers.cloudflare.com/durable-objects/examples/websocket-hibernation-server/), [DO rules](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/) and [native rate-limit binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/), checked 2026-09-04. Pinned Wrangler/types versions were verified against the official npm registry. The current rate-limit binding documentation does not state a paid-plan prerequisite; no account entitlement or billing change has been made or assumed verified.
